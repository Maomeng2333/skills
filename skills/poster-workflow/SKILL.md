# 通用海报自动生成

在当前对话完成海报制作，默认输出实际 PNG 与简短说明。主题和素材足够时连续完成文案、设计、出图、检查、交付；只有改变事实、无法读取必要素材或缺少关键交付要求时，集中询问缺失信息。用户已有的明确选择直接沿用。

## 1. 整理输入

读取用户主题、已有文案、照片、Logo、二维码和参考图。图片先实际查看，再决定如何使用。参考样式提取配色、构图、字体气质和信息层级，按本次内容重新设计。

建立本次输出目录，保存 `brief.json`。字段参考 [brief.example.json](references/brief.example.json)，仅写本次实际需要的内容：

- 主题、海报类型、目标受众、用途、比例或尺寸、风格、需要几张。
- 用户提供的事实与必须逐字保留的文案；价格、日期、地点、联系方式、品牌名和资格条件标为受保护内容。
- 素材的真实路径及用途：主图、Logo、二维码、参考样式。

未指定时：中文、数字发布、竖版 3:4、先做 1 张完整方案。用户只给主题时，可补创意标题和视觉方向；未提供的价格、日期、地址、电话及真实产品性能省略，不编成事实。需要这些信息才能使用的海报先输出明显标明的草稿，列出待补项目。用户只要求工作流时，以自有主题或明确虚构的场景演示，不假装用户已经提供品牌素材。

按 [type-recipes.md](references/type-recipes.md) 选择类型；混合场景以主要行动为中心组合模块。类型清单是起点，不能把所有海报强行套成促销版式。

## 2. 写文案并选版式

把内容整理为主标题、补充说明、最多 4 个核心信息点和一个行动提示。先保证事实和信息完整，再压缩文字密度；较长的用户原文可以做信息版或多页，逐字保留要求优先。

选择一种与主题匹配的视觉方向并直接制作。用户要求多方向时，再给差异明确的版本。保持标题、视觉主体、行动信息的层级。针对用户指定比例重新布局，关键内容保持安全边距。

## 3. 选择出图方式

### 创意图片模式

需要照片、插画、质感或图像变体时，使用可用的 `imagegen` 技能和内置图像生成工具。完整海报或现有图像修改都由该工具生成或编辑。输入真实素材时明确保留范围，把短文案逐字列入提示词；输出后逐项检查。

提示词包含用途、比例、主题、主体、构图、配色、字体层级、逐字文案、素材角色和保留条件。图片工具返回后，使用其原生媒体结果展示；项目素材有本地路径时保留到本次输出目录。

### 精确版式模式

用户要求数字、较多中文、Logo、二维码或固定像素尺寸准确时，可以从原始素材新建 HTML/CSS 海报版式。原图作为未改动的资源嵌入；文字由排版引擎输出。需要新视觉素材时先用 `imagegen` 生成主图，再把该主图作为新建版式的资源。已有海报的像素内容修改仍通过图像编辑工具完成。

使用 [render-poster.cjs](scripts/render-poster.cjs) 渲染 `brief.json`：

```text
node scripts/render-poster.cjs --brief <brief.json> --out <output-directory>
```

脚本需要 Node.js、Playwright 和 Chromium 系浏览器。优先通过 `load_workspace_dependencies` 找到已有运行库，在调用进程设置 `NODE_PATH`；用 `--browser <browser.exe>` 指定可用浏览器。缺失时可以继续使用创意图片模式；不要未经用户要求另开外部图像服务或索取 API 密钥。精确模式不是后台服务，它由当前对话触发运行。

二维码使用用户原始图片，保持白色留边；Logo 和产品图片默认完整显示。原始素材未提供时省略相应模块。扫码可用性只有实际解码成功后才能报告通过；视觉清晰或复制原图不等于已验证扫码。

## 4. 检查、修正和导出

查看真实输出，逐项核对：

1. 用户主题、类型、风格、比例、张数是否吻合。
2. 标题和受保护事实是否逐字正确，有无漏字、乱码、错误数字或无依据的补充。
3. 文字是否清晰，元素有无遮挡、挤压、越界；缩小预览后标题与主要行动仍可辨认。
4. Logo、产品、人物和二维码是否符合用户要求，必要的真实性或扫码检查是否实际完成。
5. 输出文件能否打开，真实像素尺寸是否符合交付要求。

发现问题直接修改并复查。创意图片模式用单项明确的图像编辑指令，精确模式修改 brief 或版式后重新渲染。连续两次未解决同一问题时切换方法，或清楚交付未解决的草稿并说明缺口，不能标成已验收成品。打印所需出血、色彩配置等只有按具体要求做过检查才报告满足。

保存 `qa.json` 或等价记录，区分文字/文件检查、视觉检查和未执行的扫码/印刷检查。生成失败时保留 brief 和已完成结果，说明阻塞点。

## 5. 交付与修改

展示成品图，附下载文件和一句用途说明。按需提供简短文案、版式源文件或不同尺寸版本。不要把提示词、方案文档或截图占位当成海报成品。

后续“换文案 / 换颜色 / 改价格 / 横版 / 再来一张”沿用原 brief，更新用户指定内容。复查受影响的文字、排版及素材；新增版本文件，保留可回退的旧版。只在用户明确要求时发布到外部平台、配置定时任务或追加批量生产。
